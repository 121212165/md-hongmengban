# hongmengMD 版本 2.0 问题清单

## 1. 文档目的

- 记录真机测试中已经确认的问题
- 区分现象、根因、影响和后续实现方向
- 作为 2.0 版本重构输入，不直接等同于 0.0.2 的修复清单

## 2. 当前已确认问题

### P2-001 编辑页高频快捷键无法随输入区缩放

#### 现象

- 进入编辑态后，软键盘弹起
- 高频 Markdown 快捷键栏没有跟随输入区域压缩或上移
- 用户在输入过程中看不到快捷键，或需要先收起键盘才能操作

#### 当前代码位置

- [EditorPage.ets](C:\Users\lenovo\DevEcoStudioProjects\hongmengMD\entry\src\main\ets\pages\main\EditorPage.ets#L97)
- [EditorPage.ets](C:\Users\lenovo\DevEcoStudioProjects\hongmengMD\entry\src\main\ets\pages\main\EditorPage.ets#L109)
- [EditorComponents.ets](C:\Users\lenovo\DevEcoStudioProjects\hongmengMD\entry\src\main\ets\components\base\EditorComponents.ets)

#### 根因

- 编辑区被固定为 `height('58%')`，不是自适应剩余空间
- 快捷键栏是普通页面组件，固定渲染在编辑器下方
- 当前实现没有键盘高度联动、焦点态压缩、输入态布局切换
- 这不是单点 bug，而是编辑页布局策略错误

#### 影响

- 高频格式化操作在手机端不可达
- 编辑效率明显下降
- 快捷键栏虽然存在，但在核心场景下接近不可用

#### 2.0 处理方向

- 把编辑页改成真正的编辑态布局
- 去掉固定高度编辑区，改为自适应 `layoutWeight`
- 快捷键栏改成紧凑工具条，只保留少量高频键
- 工具条围绕编辑器布局，不再作为页面底部大工具栏存在
- 输入态与非输入态使用不同布局密度

#### 实现建议

1. 编辑页拆成顶部导航、中部编辑器、底部紧凑工具条
2. 工具条仅保留 `Heading / List / Task / Quote / Bold / Code`
3. 自动保存状态和字数统计移出底部主操作区
4. 后续如需更强能力，再评估键盘联动或输入附件式方案

### P2-002 Editor 页点击 Workspace 实际退出应用

#### 现象

- 在编辑页点击 `Workspace`
- 应用表现为直接关闭或退回桌面
- 用户感知为“点击 Workspace 闪退”

#### 当前代码位置

- [EntryAbility.ets](C:\Users\lenovo\DevEcoStudioProjects\hongmengMD\entry\src\main\ets\entryability\EntryAbility.ets#L31)
- [EditorPage.ets](C:\Users\lenovo\DevEcoStudioProjects\hongmengMD\entry\src\main\ets\pages\main\EditorPage.ets#L67)

#### 根因

- 应用首屏仍然由 `EntryAbility` 直接加载 `pages/main/EditorPage`
- `EditorPage` 中的 `Workspace` 按钮调用的是 `router.back()`
- 当编辑页本身就是路由栈首屏时，`back()` 没有上一级页面可返回
- 最终结果不是“返回工作区”，而是直接退出当前界面

#### 影响

- 三页式结构在真机上的导航语义被破坏
- 用户无法从编辑页稳定返回工作区
- 这会误导用户认为工作区页面不可用或应用不稳定

#### 2.0 处理方向

- 统一入口页和路由策略
- 让 `WorkspacePage` 成为应用主入口
- `EditorPage` 和 `PreviewPage` 只作为二级页面进入
- 不再在首屏页面上使用语义不清的 `router.back()` 返回工作区

#### 实现建议

1. 将 `EntryAbility` 首屏切换为 `pages/main/WorkspacePage`
2. 编辑页的 `Workspace` 按钮仅作为“返回上一页”或“显式跳转工作区”之一
3. 预览页同样遵循统一导航策略，避免一部分页面 `back`、另一部分页面 `push`
4. 完成后补一轮真机导航回归测试

## 3. 优先级判断

这两个问题都不属于“以后再看”的低优先级细节。

- `P2-001` 是编辑体验主问题，直接影响产品是否可用
- `P2-002` 是导航结构问题，直接影响三页式架构是否成立

如果进入 2.0 重构阶段，这两项都应进入首批任务。

## 4. 结论

2.0 版本至少需要先完成两件事：

1. 重做编辑页布局，让高频快捷键在输入态可用
2. 重做页面入口和返回逻辑，让工作区成为稳定导航起点

这两个问题解决之前，不应继续扩展更多页面功能或交互层能力。
