# hongmengMD 版本 0.0.2 目标与后续规划

## 1. 文档目的

- 记录 `0.0.2` 版本的真实目标，避免功能继续无边界膨胀。
- 明确当前版本聚焦的能力、暂不实现的能力，以及后续版本的演进方向。
- 为后续 UI 重构、导出闭环、导入能力和文件管理提供统一约束。

## 2. 产品定位

`hongmengMD` 在 `0.0.2` 阶段的定位是：

一个本地优先的 Markdown 内容工作台。

核心闭环是：

`创建 / 导入内容 -> 编辑 -> 预览 -> 导出 / 分享`

这意味着当前版本不再承诺：

- 多设备同步
- 跨设备接力
- 系统备忘录同步
- 系统级搜索
- Agent 能力

## 3. 版本 0.0.2 的目标

### 3.1 核心目标

- 把当前工程从“功能堆叠的演示版”收敛成“单机可用的 Markdown 工具”。
- 解决真机测试中已经暴露的高频问题：
  - 快捷键被输入法遮挡
  - 导出不可见
  - 分享不可用
  - 编辑与预览同屏导致 UI 混乱
  - 工作区切换体验弱

### 3.2 用户可感知目标

- 用户可以新建或导入文档。
- 用户可以在手机上持续编辑 Markdown 内容。
- 用户可以在清晰的预览页确认渲染效果。
- 用户可以把文件导出到可见位置，并能够分享出去。
- 用户可以管理自己的工作区和文档，而不是只在单页里堆卡片。

### 3.3 验收标准

- 应用启动稳定，无白屏、无首屏崩溃。
- 编辑页在软键盘弹出时，常用快捷操作仍可触达。
- 自动保存有效，应用切后台或重启后内容不丢失。
- 导入、导出、分享形成可走通的本地闭环。
- 工作区切换和文档切换路径明确，用户能快速找到当前内容。

## 4. 0.0.2 范围内保留的内容

### 4.1 必做能力

- 工作区管理
- 文档列表与切换
- 新建文档
- 基础模板入口
- Markdown 编辑
- 自动保存
- 预览模式
- 文件导入
- 真实导出
- 系统分享
- 文件管理

### 4.2 可以保留但不强调的能力

- 基础模板

模板仅作为新建辅助，不作为主卖点。`0.0.2` 只保留弱模板：

- 空白笔记
- 文章
- 会议纪要

## 5. 0.0.2 明确不做的内容

以下能力从 `0.0.2` 范围中移除，不进入当前版本承诺：

- 多设备接力
- 多设备同步
- 系统级搜索
- 系统备忘录同步
- Agent 能力
- 模板强化

说明：

- 如果界面中仍保留相关入口，应在 `0.0.2` 开发中移除或降级，避免继续造成错误预期。

## 6. 0.0.2 的页面结构目标

当前单页结构信息密度过高，不适合继续扩展。`0.0.2` 应调整为三页式结构。

### 6.1 工作区页

职责：

- 查看工作区
- 切换工作区
- 查看文档列表
- 新建文档
- 导入文件

不承担：

- 大段内容编辑
- 渲染预览
- 导出记录展示
- 接力状态展示

### 6.2 编辑页

职责：

- 编辑正文
- 修改标题
- 自动保存
- 提供少量高频 Markdown 快捷键

要求：

- 快捷键不再采用当前底部固定栏堆叠模式
- 快捷键必须避开输入法遮挡区域
- 编辑页不再与完整预览页同屏展示

### 6.3 预览 / 导出页

职责：

- 查看渲染结果
- 选择导出格式
- 执行导出
- 执行分享

要求：

- 导出结果对用户可见
- 用户能知道文件去了哪里
- 分享链路可以直接调用系统能力

## 7. 0.0.2 的关键设计原则

### 7.1 单机闭环优先

先把“本地写作闭环”做好，再考虑系统集成和跨设备能力。

### 7.2 编辑体验优先

手机端最重要的是输入效率，不是把所有能力都放在首屏。

### 7.3 结构清晰优先

浏览、编辑、预览必须分工明确，避免继续把所有模块堆进一个页面。

### 7.4 文件可见优先

导出结果必须进入用户可感知、可定位、可分享的路径。

## 8. 0.0.2 计划解决的问题

### 8.1 交互问题

- 快捷键栏会被输入法遮挡
- 编辑与预览同屏导致注意力分散
- 工作区切换入口不明确

### 8.2 文件问题

- 导出结果写入私有目录，用户找不到
- 导出格式存在占位实现，无法作为真实能力使用
- 缺少导入入口

### 8.3 产品问题

- 模板价值低
- 页面功能过多，真机体验混乱
- 用户无法理解当前应用到底主打什么

## 9. 后续版本规划

## 9.1 版本 0.0.3

目标：

- 把 `0.0.2` 的本地内容闭环打磨完整
- 补足易用性与稳定性

建议内容：

- 优化工作区和文档管理
- 补充导出后的打开、查看与反馈体验
- 提升 Markdown 快捷键的插入效率
- 加强导入后的格式清理与兼容
- 补充真机测试与回归测试清单

## 9.2 版本 0.0.4

目标：

- 增强内容资产管理，而不是扩张到跨设备能力

建议内容：

- 最近文件与最近导出入口
- 文档分组、排序、筛选
- 更完整的导出格式表现
- 预览页与导出页体验细化

## 9.3 版本 0.1.0 之后可重新评估的方向

以下方向仅在本地闭环稳定后重新评估，不提前进入当前承诺：

- 多设备接力
- 多设备同步
- 系统搜索接入
- 系统备忘录同步
- Agent 能力

评估原则：

- 必须先证明单机版本已经稳定、易用、可持续维护。
- 必须有清晰的底层架构入口，不能再以页面堆功能的方式接入。

## 10. 当前开发约束

- 不再继续扩展“内容接力”相关功能。
- 不再把“跨设备协同”作为当前版本卖点。
- 不再把模板系统作为当前阶段重点。
- 优先投入到 UI 重构、导入导出、分享、文件管理。

## 11. 一句话总结

`0.0.2` 的任务不是把功能做多，而是把产品做实。

先完成一个本地优先、结构清晰、可导入、可导出、可分享的 Markdown 工具，再决定是否进入跨设备和智能能力阶段。
