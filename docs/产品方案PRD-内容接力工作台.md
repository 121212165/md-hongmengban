# hongmengMD 产品方案 PRD（V1 初稿）

## 1. 产品定义

### 1.1 产品名称

- 当前项目名：`hongmengMD`
- 建议产品方向名：`内容接力工作台`

### 1.2 产品一句话

在手机上捕捉，在平板上整理，在电脑上发布的鸿蒙分布式内容工作台。

### 1.3 产品定位

这不是一个单纯的 Markdown 编辑器，也不是一个与 Obsidian 正面竞争的第二大脑工具，而是一个面向鸿蒙多设备场景的“内容生产接力器”。

产品核心价值：

- 帮用户在移动场景下快速开始写作
- 帮用户在鸿蒙设备之间无缝接力内容创作
- 帮用户把草稿高效变成可发布内容
- 用鸿蒙分布式能力做出传统 MD 编辑器做不到的体验

### 1.4 与市场同类产品的差异

当前主流手机版 Markdown 工具普遍具备：

- Markdown 编辑
- 常用快捷键
- 预览只读
- 基础导出

这些能力已经成为标配，不足以形成产品壁垒。

本产品的差异点不是“更全的 Markdown 语法支持”，而是：

- 更快：打开即写，桌面卡片即入口
- 更顺：跨设备流转，而不是手动同步文件
- 更外向：面向“写完即发”，而不是“写完存库”
- 更鸿蒙：围绕分布式流转、万能卡片、系统级分享和搜索重构体验

## 2. 用户与场景

### 2.1 核心目标用户

第一优先级：

- 技术内容创作者
- 开发者
- 使用手机、平板、PC 混合办公的鸿蒙生态用户

第二优先级：

- 轻量知识管理用户
- 学生与研究者中的结构化写作者

第三优先级：

- 移动办公用户

### 2.2 为什么他们会用

他们不是缺一个 Markdown 编辑器，而是缺一个更适合移动端与多设备协作的内容生产工具。

他们的真实问题是：

- 灵感发生在手机上，但成稿通常完成在大屏设备上
- 现有 MD 工具在手机端要么太重，要么只是简单编辑器
- 写完后还要手动复制、导出、排版、再发布
- 跨设备继续写这件事通常很割裂

### 2.3 核心使用场景

场景 1：通勤快记

- 用户在手机桌面卡片上快速记下文章开头、会议纪要或技术灵感
- 应用自动保存为草稿

场景 2：跨设备接力

- 用户回到工位后，将手机上的草稿流转到平板或 PC
- 在大屏上继续完善结构、插入内容、检查预览

场景 3：面向发布的整理

- 用户将草稿整理为博客文章、GitHub README、会议纪要或学习笔记
- 一键导出为 Markdown、PDF、长图或可复制富文本

场景 4：鸿蒙设备协同写作

- 手机作为素材和输入端
- 平板作为主编辑端
- PC 作为最终输出端

## 3. 产品目标

### 3.1 业务目标

- 在鸿蒙生态中建立“分布式内容创作工具”的差异化认知
- 避免落入泛 Markdown 编辑器红海
- 形成适合应用市场推荐的鲜明产品卖点

### 3.2 用户目标

- 让用户在 3 秒内开始写第一段内容
- 让用户在不同设备上继续写作时没有割裂感
- 让用户在完成写作后能快速输出和分享

### 3.3 版本目标

V1 聚焦于验证三件事：

- 快速记录是否成立
- 跨设备接力是否有明显价值
- 输出发布链路是否足够顺畅

## 4. 产品原则

- 先解决高频问题，不追求 Markdown 功能堆叠
- 先做鸿蒙独有价值，不做 Android/iOS 的普通移植版
- 先服务内容生产，不做重型知识库
- 先做流畅、低门槛、强闭环，再做高级能力

## 4.1 设计原则

### 4.1.1 设计目标

第一版界面的核心不是“功能塞满”，而是建立一种简洁、克制、可信但不廉价的产品气质。

需要避免的方向：

- 工具味太重，像练手项目
- 组件堆砌，像普通记事本
- 只有白底黑字，缺少产品辨识度
- 所有页面视觉层级过平，显得便宜

需要建立的方向：

- 简洁，但有明确的品牌感
- 克制，但有微设计细节
- 专业，但不冰冷
- 新颖，但不花哨

### 4.1.2 视觉气质关键词

- 安静
- 精准
- 留白
- 柔和层次
- 轻微科技感
- 内容优先

### 4.1.3 微设计原则

第一版虽然不展开页面设计，但必须提前约束这些细节方向：

- 交互反馈要轻，不要“重按钮感”
- 卡片和容器的层次要靠细微阴影、边界和间距建立，不靠大面积颜色堆叠
- 状态变化要有轻量动效，例如流转、保存、连接成功、导出完成
- 字体层级要清晰，避免所有文字都一个重量
- 空状态、加载态、保存态必须体现产品温度

### 4.1.4 设计判断标准

后续 UI 是否合格，可以用这四条判断：

1. 第一眼能否看出这是一个“产品”，而不是课程作业
2. 用户是否愿意在这个界面停留和继续写
3. 是否能体现“跨设备接力”的高级感
4. 是否能在保持简洁的前提下保留识别度

## 5. 核心能力设计

### 5.1 模块一：快记入口

定位：

- 所有内容创作的起点

核心能力：

- 打开应用即新建或进入最近草稿
- 桌面万能卡片直接创建草稿
- 自动保存
- 基础 Markdown 快捷栏
- 最近文档恢复

关键价值：

- 比传统 Markdown 编辑器更快进入创作状态

### 5.2 模块二：接力写作

定位：

- 鸿蒙差异化核心模块

核心能力：

- 草稿在手机、平板、PC 间无缝流转
- 支持从当前设备继续编辑，不依赖手动文件同步
- 手机作为辅助输入端或快捷操作端
- 跨设备共享剪贴板与素材

关键价值：

- 把“换设备继续写”从文件传输问题变成系统级能力

### 5.3 模块三：结构化整理

定位：

- 对草稿做轻量项目化管理

核心能力：

- 以“项目”组织内容
- 项目内包含文档、素材、待办和导出记录
- 提供最近编辑、收藏、草稿箱
- 支持基础标签和分类

关键价值：

- 不做庞杂知识库，但保证内容不会散乱

### 5.4 模块四：输出发布

定位：

- 从写作完成走向发布和交付

核心能力：

- 导出 Markdown
- 导出 PDF
- 导出长图
- 复制富文本
- 面向博客、GitHub、公众号等场景做适配

关键价值：

- 解决“写完之后还要再折腾一遍”的问题

## 5.5 非页面优先落地板块

当前阶段先不进入页面视觉设计，优先把产品底层板块定义清楚。

### 5.5.1 内容模型

需要先明确系统中的核心对象：

- 草稿
- 正式文档
- 项目
- 素材
- 导出任务
- 设备会话

建议的数据关系：

- 一个项目包含多个文档
- 一个文档关联多个素材
- 一个文档可产生多个导出记录
- 一个文档可以存在当前设备会话和接力会话

### 5.5.2 接力模型

接力不是“同步文件”，而是“继续当前任务”。

因此需要先定义：

- 当前写作会话
- 可接力目标设备
- 接力状态：待接收、接力中、已接力、失败
- 接力后的恢复策略

接力体验要保证：

- 用户知道自己把什么接给了哪台设备
- 目标设备能恢复到尽可能接近原状态
- 接力失败时草稿不会丢

### 5.5.3 输出模型

输出不是单一导出按钮，而是一个完整链路。

建议先定义四种输出结果：

- Markdown 文件
- PDF
- 长图
- 富文本

每种输出都应记录：

- 输出时间
- 输出来源文档
- 输出格式
- 是否成功
- 最近一次输出目标

### 5.5.4 项目体系

项目不是文件夹替代，而是围绕目标任务组织内容。

第一版建议项目类型固定化，而不是完全自由创建：

- 文章
- 会议纪要
- 学习笔记
- GitHub 草稿

这样做的好处：

- 降低创建成本
- 便于后续增加模板
- 有助于形成产品的内容结构感

### 5.5.5 设备体系

既然产品核心是鸿蒙接力，就必须把设备关系当成一级能力定义。

第一版应先明确：

- 当前在线设备列表
- 可接力设备识别
- 最近接力设备
- 当前设备角色

设备角色建议分为：

- 快记端
- 主编辑端
- 输出端

这样后续产品文案和交互语义会更统一。

## 6. 鸿蒙特色能力映射

### 6.1 分布式流转

产品应用方式：

- 手机写到一半，流转到平板继续编辑
- 平板预览，手机辅助输入
- PC 上做最终导出和交付

产品意义：

- 这是与普通 MD 编辑器最本质的差异

### 6.2 万能卡片

产品应用方式：

- 桌面卡片展示最近草稿
- 卡片一键新建
- 卡片展示今日待整理内容

产品意义：

- 让写作入口前置到系统桌面

### 6.3 系统分享与搜索

产品应用方式：

- 从浏览器、相册、备忘录、聊天内容快速分享到应用中形成草稿
- 文档支持进入系统全局搜索

产品意义：

- 让内容工作台不是信息孤岛

### 6.4 原生性能

产品应用方式：

- 使用 ArkTS 与原生 UI 保证编辑、滚动、预览和切换流畅

产品意义：

- 在手机与平板上处理长文本时获得更稳定体验

## 8. MVP 范围

### 8.1 V1 必做

- 首页最近草稿与快速新建
- Markdown 编辑
- 常用快捷栏
- 自动保存
- 基础预览
- 项目化组织
- 跨设备流转基础能力
- 导出 Markdown / PDF / 长图

- 插件市场
- 重型知识图谱
- 双向链接体系
- 实时多人协作
- 复杂权限体系

## 8.3 V1 第一优先级拆解

基于当前讨论，第一版最先落实的不是页面，而是下面四条主线：

1. 快记与自动保存
2. 跨设备接力基础链路
3. 项目化内容组织
4. 导出与发布输出

这四条主线跑通之后，再进入视觉层设计，会更容易避免“好看但空”的问题。

## 8.5 字段级对象模型

这一部分用于把产品语言转换成研发可实现的数据对象。

### 8.5.1 Draft 草稿

用途：

- 承接所有尚未完成的创作内容

建议字段：

- `id`
- `title`
- `content`

- `sourceType`

- `lastSessionId`：最近编辑会话

### 8.5.2 Document 正式文档

用途：

- 进入长期留存与整理阶段的正式内容

建议字段：

- `id`
- `title`
- `content`
- `projectId`
- `docType`
- `format`
- `createdAt`
- `updatedAt`
- `publishedAt`
- `status`
- `coverAssetId`
- `wordCount`
- `lineCount`

字段说明：

- `docType`：如文章、会议纪要、学习笔记、GitHub 草稿
- `format`：第一版固定为 `markdown`
- `status`：可取 `draft`、`active`、`archived`、`exported`
- `version`：用于后续版本快照

### 8.5.3 Project 项目

用途：

建议字段：

- `createdAt`
- `updatedAt`
- `coverStyle`
- `sortOrder`

字段说明：

- `projectType`：文章、会议纪要、学习笔记、GitHub 草稿
- `status`：可取 `active`、`completed`、`archived`

### 8.5.4 Asset 素材

用途：

建议字段：

- `assetType`
- `name`
- `localPath`

- `source`

字段说明：

- `assetType`：图片、链接、文本片段、附件
- `source`：来源于相册、系统分享、剪贴板、拖拽

### 8.5.5 ExportTask 导出任务

用途：

- 记录每次输出和发布行为

建议字段：

- `projectId`

- `status`

字段说明：

- `exportType`：markdown、pdf、long_image、rich_text
- `target`：本地保存、复制、分享、平台发布

### 8.5.6 Device 会话设备

用途：

- 管理可接力设备和当前设备角色

建议字段：

- `id`
- `deviceName`
- `deviceType`
- `online`
- `lastSeenAt`
- `role`
- `capabilities`

字段说明：

- `deviceType`：phone、tablet、pc
- `role`：快记端、主编辑端、输出端

### 8.5.7 RelaySession 接力会话

用途：

- 记录一次跨设备接力过程

建议字段：

- `id`
- `documentId`
- `fromDeviceId`
- `toDeviceId`
- `status`
- `startedAt`
- `acceptedAt`
- `finishedAt`
- `snapshot`
- `errorMessage`

字段说明：

- `status`：pending、accepted、transferring、completed、failed、cancelled
- `snapshot`：保存接力瞬间的上下文，如滚动位置、光标位置、预览状态

## 8.6 核心状态流转

### 8.6.1 草稿状态流转

- 新建后进入 `editing`
- 用户离开当前文档进入 `paused`
- 满足输出条件后进入 `ready_to_publish`
- 导出成功后仍可回到 `editing`

### 8.6.2 接力状态流转

- 发起后进入 `pending`
- 目标设备确认后进入 `accepted`
- 数据传输中进入 `transferring`
- 恢复成功进入 `completed`
- 中断则进入 `failed` 或 `cancelled`

### 8.6.3 导出状态流转

- 创建导出任务进入 `queued`
- 实际执行进入 `processing`
- 成功进入 `success`
- 失败进入 `failed`

建议第一版后半程或第二阶段完成。

## 8.8 研发排期建议

## 8.9 验收清单

### 内容层验收

- 新建草稿后 3 秒内可开始输入
- 应用退出再进入，草稿内容仍在
- 最近草稿列表准确可恢复

### 接力层验收

- 可识别至少一个目标设备
- 发起接力后目标设备能接收当前文档
- 接力失败不会丢草稿

### 输出层验收

- 四种输出都能触发
- 至少两种输出可真实落地使用
- 导出失败有明确提示

### 项目层验收

- 文档可归属到项目
- 项目可按类型区分
- 最近项目可快速进入

## 9. 页面原型建议

### 9.1 首页

目标：

- 打开就能继续

结构建议：

- 顶部：欢迎语 + 当前设备状态
- 中部：最近编辑文档卡片
- 中部：新建按钮组
- 底部：接力到其他设备入口

### 9.2 编辑页

目标：

- 写作和预览同屏，接力入口清晰

结构建议：

- 顶部：返回、标题、保存状态、接力
- 主体：上半编辑，下半预览
- 底部：Markdown 快捷栏

### 9.3 项目页

目标：

- 轻量组织，不增加理解成本

结构建议：

- 顶部：项目切换与筛选
- 中部：文档列表
- 侧重最近、待整理、已导出状态

## 10. 关键交互流程

### 10.1 快记流程

1. 用户点击桌面卡片
2. 系统直接进入新草稿
3. 输入内容后自动保存
4. 草稿出现在首页最近列表

### 10.2 接力流程

1. 用户在手机上编辑
2. 点击“接力到设备”
3. 选择平板或 PC
4. 目标设备直接进入当前文档编辑页

### 10.3 发布流程

1. 用户完成写作
2. 点击导出/发布
3. 选择 Markdown、PDF、长图或富文本
4. 分享到目标平台或保存本地

## 11. 成功指标

建议跟踪以下指标：

- 首次打开到开始输入的耗时
- 草稿自动保存成功率
- 跨设备流转使用率
- 导出使用率
- 最近草稿二次打开率
- 7 日留存

## 12. 风险与挑战

### 12.1 产品风险

- 如果跨设备接力体验不明显，产品会退化为普通 Markdown 编辑器
- 如果输出发布链路不顺，用户价值感会下降

### 12.2 技术风险

- 分布式流转在不同设备组合下的一致性
- 多端状态恢复与草稿同步稳定性
- 大文本编辑和预览性能

### 12.3 市场风险

- 用户容易把产品误解为普通 MD 编辑器
- 需要在命名和文案上明确“内容接力工作台”的差异化认知

## 13. 后续版本方向

### 13.1 V2

- 更好的发布适配
- 图片与素材管理
- 模板系统
- 语音转草稿

### 13.2 V3

- 面向 GitHub 的深度集成

- 轻量协作评论

## 14. 本阶段结论

`hongmengMD` 不应该继续作为一个简单的 Markdown 编辑器演进。

更合理的产品方向是：

- 以 Markdown 作为基础表达格式
- 以鸿蒙分布式能力作为核心差异化
- 以“快速开始、跨设备接力、面向发布输出”作为产品主线

- 一份更短的立项版产品摘要
- 一份页面级低保真原型说明

在进入页面设计前，应继续先完成三件事：

- 明确产品视觉气质与设计判断标准
- 把非页面板块拆成研发可落地对象
- 先验证“接力”和“输出”是否真正有产品价值
