# hongmengMD 版本 0.0.2 技术路线与项目边界

## 1. 文档目的

- 把 `0.0.2` 的产品目标转成可执行的工程路线。
- 约束项目边界，避免再次回到“单页堆功能”的状态。
- 为页面重构、导入导出、分享和文件管理提供统一实现方向。

## 2. 当前工程基线

### 2.1 当前页面结构

当前主入口是单页工作台：

- `entry/src/main/ets/pages/main/EditorPage.ets`

页面中同时承载了以下职责：

- 工作区浏览
- 模板新建
- 草稿列表
- 快捷操作
- 编辑
- 预览
- 接力记录
- 导出记录

这导致当前问题：

- 信息密度过高
- 编辑态与浏览态混杂
- 快捷键与输入法冲突
- 预览区与编辑区争夺屏幕高度

### 2.2 当前服务结构

当前核心服务集中在：

- `entry/src/main/ets/services/FileService.ets`
- `entry/src/main/ets/services/ProjectService.ets`
- `entry/src/main/ets/services/ExportService.ets`
- `entry/src/main/ets/services/RelayService.ets`

当前结构特点：

- `FileService` 既负责持久化，也负责文档、工作区、导出、快照、接力记录。
- 服务层职责过重，但对于 `0.0.2` 仍可接受，只要继续做“拆层”而不是再加职责。
- `RelayService` 与 `ExportService` 目前更像薄封装，不具备独立业务能力。

### 2.3 当前能力状态

已存在的真实能力：

- 本地 Preferences 持久化
- 基础工作区与文档切换
- Markdown 编辑
- 简化预览
- 自动保存
- 本地导出记录

当前未完成或只做了占位的能力：

- 真实文件导出
- 系统分享
- 文件导入
- 可见文件管理
- 编辑态快捷栏避让
- 三页式结构

## 3. 0.0.2 项目边界

### 3.1 本版本必须完成

- 三页式信息架构
- 本地工作区与文档管理
- Markdown 编辑与自动保存
- 预览模式
- 文件导入
- 真实导出
- 系统分享
- 用户可见的文件落盘与反馈

### 3.2 本版本明确不做

- 多设备同步
- 多设备接力
- 系统搜索
- 系统备忘录同步
- Agent 能力
- 模板增强系统
- 云端账号体系
- 复杂协同编辑

### 3.3 边界原则

- 不为未来能力提前引入过重架构。
- 不为了保留“概念卖点”继续保留伪功能入口。
- 不把跨设备能力和智能能力混入 `0.0.2` 主流程。
- 只做本地内容闭环所必需的页面、服务和数据结构调整。

## 4. 目标架构

## 4.1 页面层

`0.0.2` 改为三页结构：

### 4.1.1 工作区页

职责：

- 展示工作区列表
- 展示当前工作区文档列表
- 新建文档
- 导入文件
- 进入编辑页

不承担：

- 正文编辑
- 完整预览
- 导出设置

### 4.1.2 编辑页

职责：

- 编辑标题与正文
- 自动保存
- 插入高频 Markdown 语法
- 跳转到预览页

要求：

- 高频快捷键不再使用页面底部固定大工具栏
- 快捷操作必须围绕编辑器布局
- 编辑页只专注输入，不展示历史记录和资产面板

### 4.1.3 预览 / 导出页

职责：

- 展示渲染结果
- 选择导出格式
- 调用导出
- 调用系统分享

要求：

- 导出和分享要基于真实文件
- 用户能看到文件路径或结果反馈

## 4.2 服务层

### 4.2.1 保留的核心服务

- `FileService`
- `ProjectService`
- `ExportService`

### 4.2.2 0.0.2 内建议的职责收敛

`FileService` 保留为本地数据中枢，但职责要往以下方向整理：

- 文档读写
- 工作区管理
- 导入导出文件访问
- 草稿持久化

`ExportService` 负责：

- 导出格式选择
- 导出任务封装
- 分享前文件准备

`ProjectService` 负责：

- 工作区列表
- 工作区切换
- 新建工作区与基础模板

### 4.2.3 0.0.2 内移除或降级

`RelayService` 不再扩展。

处理原则：

- 不再作为主流程依赖
- 不再作为版本卖点
- 如保留代码，仅允许处于未接入主页面的低优先级状态

## 4.3 数据层

`0.0.2` 继续以本地数据为主，不引入云同步模型。

建议保留的核心数据对象：

- `Project`
- `Document`
- `ExportTask`
- `DraftSnapshot`

建议弱化的数据对象：

- `RelaySession`

数据约束：

- 文档永远归属一个工作区
- 当前文档与当前工作区状态分离保存
- 导出记录必须保存输出路径、格式、时间和状态
- 导入记录不是必须，但导入后的文档元数据要完整

## 5. 技术路线

## 5.1 阶段一：页面拆分与主流程重建

目标：

- 把单页工作台拆成三页结构
- 先把 UI 结构问题解决

主要动作：

- 新建工作区页
- 新建编辑页
- 新建预览 / 导出页
- 调整入口路由和页面跳转
- 删除当前主页面中的混合布局

阶段结果：

- 浏览、编辑、预览三态分离
- 输入法遮挡问题有明确承载面可处理

## 5.2 阶段二：导出与分享闭环

目标：

- 把当前占位导出改成真实能力

主要动作：

- 落盘到用户可感知位置或可明确反馈的文件位置
- 调整不同导出格式的真实输出策略
- 接入系统分享
- 补充导出成功 / 失败反馈

阶段结果：

- 用户能真正拿到文件
- 分享可从应用直接完成

## 5.3 阶段三：导入与文件管理

目标：

- 建立输入和输出都可达的内容资产流

主要动作：

- 接入本地文件选择
- 支持导入 Markdown / Text
- 导入后生成文档并归档到工作区
- 补足文档列表和工作区管理细节

阶段结果：

- 应用不再只有“新建内容”，也能接收外部内容

## 5.4 阶段四：收口与回归

目标：

- 完成 `0.0.2` 可交付版本

主要动作：

- 清理伪入口和废弃文案
- 回归真机测试
- 处理关键 warning 和阻塞问题
- 对外文档同步为本地优先产品描述

阶段结果：

- 版本叙事、代码实现、真机体验三者一致

## 6. 实现原则

### 6.1 先拆页面，再补功能

如果不先解决结构问题，继续加导入导出只会把页面进一步做乱。

### 6.2 先做真实能力，再做视觉包装

导出、分享、文件可见性属于产品基本盘，优先级高于视觉修饰。

### 6.3 先做本地可闭环，再谈系统集成

导入、编辑、预览、导出、分享闭环未完成时，不应该重新引入跨设备或 Agent。

### 6.4 减少伪能力入口

凡是 `0.0.2` 不做的能力，不应继续在主流程里高显性展示。

## 7. 风险与应对

### 7.1 页面拆分导致状态流变复杂

风险：

- 当前状态都集中在 `EditorPage`
- 拆页后容易出现当前文档和当前工作区同步不一致

应对：

- 统一由 `FileService` 维护当前工作区和当前文档
- 页面只读状态，不自行维护第二套主状态

### 7.2 HarmonyOS 文件访问与分享接入复杂

风险：

- 不同目录可见性不同
- 分享链路依赖系统能力调用

应对：

- 先定义最小可用路径策略
- 先实现 Markdown / Text 文件稳定导出
- 再补 PDF / 长图等复杂格式

### 7.3 老代码遗留入口影响产品认知

风险：

- 接力、历史记录、模板入口仍然存在
- 用户继续误解应用能力边界

应对：

- 在 `0.0.2` 中同步删除或隐藏无关入口

## 8. 0.0.2 的完成定义

`0.0.2` 完成时，应满足以下条件：

- 用户能从工作区页进入任意文档
- 用户能在编辑页高效输入 Markdown
- 用户不会因为输入法而失去高频格式操作
- 用户能在预览页确认内容结果
- 用户能把文件导出并分享出去
- 用户能导入本地文件形成新文档
- 应用不再展示跨设备与 Agent 等超出版本边界的主流程能力

## 9. 一句话路线结论

`0.0.2` 的工程路线不是继续堆功能，而是围绕“本地内容闭环”重建页面结构、导入导出和文件管理能力。
