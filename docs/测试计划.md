# hongmengMD 测试计划

## 1. 目标

- 验证 `hongmengMD` 在 HarmonyOS `6.0.2(22)` 下的可构建性、核心编辑流程、文档持久化、Markdown 预览和基础稳定性。
- 将现有测试从“有样例”提升到“可持续回归”，覆盖单元测试、组件逻辑测试、设备侧测试和手工验收。
- 为后续接入 DevEco Studio 本地执行或 CI 提供统一入口。

## 2. 项目现状

### 2.1 当前代码范围

- 主页面为双栏编辑器，包含侧边栏文件列表、编辑区、预览区、工具栏和字数统计。
- 主要业务模块：
  - `entry/src/main/ets/pages/main/EditorPage.ets`
  - `entry/src/main/ets/services/FileService.ets`
  - `entry/src/main/ets/common/utils/MarkdownParser.ets`
  - `entry/src/main/ets/models/DocumentModel.ets`
  - `entry/src/main/ets/components/base/EditorComponents.ets`
  - `entry/src/main/ets/components/base/PreviewComponents.ets`

### 2.2 当前测试基础

- 已配置 `@ohos/hypium`、`@ohos/hamock`。
- 已存在本地测试清单：`entry/src/test/test List.json`。
- 已存在设备侧测试目录：`entry/src/ohosTest/ets/test`。
- `entry/build-profile.json5` 已声明 `default` 和 `ohosTest` 两个 target。

### 2.3 当前风险

- 项目根目录未提交 `hvigorw` wrapper，`local.properties` 也未配置 SDK 路径，当前环境不满足稳定复现测试的最低条件。
- 现有部分测试更像占位样例，不直接校验组件真实行为。
- 部分中文字符串出现编码异常，相关断言容易失真。
- 某些断言依赖 `Date.now()` 的即时值，存在天然不稳定性。

  - `ohosTest`
  - UI 冒烟
  - 持久化与异常恢复验证

## 5. 测试策略

### 5.1 L0 构建与基础校验

目标：任何改动先保证能构建、能安装、能启动。

检查项：

- 依赖安装成功
- `entry` 模块 debug 构建成功
- `ohosTest` target 构建成功
- HAP 安装成功
- 应用冷启动成功，无首屏崩溃

建议命令：

```powershell
ohpm install
hvigorw --mode module -p module=entry@default assembleHap
hvigorw --mode module -p module=entry@ohosTest assembleHap
```

如果项目最终仍以 DevEco Studio 为主执行，则以上命令对应为 IDE 中的同步依赖、构建 `entry/default` 和构建 `entry/ohosTest`。

### 5.2 L1 单元与纯逻辑测试

目标：覆盖不依赖设备上下文的纯业务逻辑。

优先级：

- `DocumentModel`
- `MarkdownParser`
- `CommonConstants`

重点用例：

- `createDocument`：
  - 自动补全 `.md`
  - 创建时间与更新时间存在且合理
  - ID 非空且唯一
- `parseMarkdown`：
  - 标题、引用、无序列表、有序列表、任务列表、代码块、分割线
  - 空文本与多行文本
  - 行内粗体、斜体、删除线、链接、代码
  - 异常输入与未闭合标记兜底
- `getWordCount`：
  - 英文、中文、混排、空字符串、换行

补强要求：

- 去掉依赖实时 `Date.now()` 精确相等的断言，改为范围断言或 mock 时间。
- 中文断言统一为 UTF-8 可读文本，避免乱码导致假失败。

### 5.3 L2 服务层测试

目标：验证 `FileService` 的真实文档生命周期，而不是只测返回值。

重点用例：

- 初始化无数据时自动创建欢迎文档
- 创建文档后文档列表数量变化
- 重命名后自动补 `.md`
- 保存内容后 `updatedAt` 更新
- 删除当前文档后自动切换到下一篇或空态
- `current.json` 与 `documents.json` 的持久化行为正确
- 文件损坏或 JSON 解析失败时可以回退到默认文档

执行建议：

- 通过 mock `UIAbilityContext.filesDir` 和文件 IO 隔离设备依赖。
- 将真实文件读写与内存逻辑拆分后再补单元测试，否则当前测试可维护性会持续偏低。

### 5.4 L3 组件与页面行为测试

目标：验证页面状态流转与组件交互逻辑。

重点用例：

- `EditorArea`
  - 输入回调触发
  - 占位文案显示
- `ToolbarPanel`
  - 按钮数量与插入文本映射一致
  - 点击按钮后内容正确追加
- `PreviewArea`
  - 空内容与非空内容显示正确
- `EditorPage`
  - 首次进入完成 `FileService.init`
  - 新建文档后列表刷新、当前文档切换成功
  - 切换文档前会保存当前内容
  - 切换主题后颜色配置同步更新
  - 删除文档后页面状态不悬空

说明：

- 当前 `EditorComponents.test.ets` 和 `PreviewComponents.test.ets` 大量是静态常量断言，应逐步改成组件行为断言或页面状态断言。

### 5.5 L4 设备侧测试与手工冒烟

目标：验证本地文件、生命周期和 UI 交互在实际设备上的表现。

冒烟场景：

1. 首次安装启动，默认欢迎文档正常展示。
2. 新建文档，输入 Markdown 内容，返回后重新进入内容仍保留。
3. 重命名文档时自动追加 `.md`。
4. 切换不同文档，内容互不串写。
5. 删除当前文档后界面自动切换到剩余文档。
6. 打开侧边栏、切换主题、使用工具栏插入文本，页面不崩溃。
7. 输入标题、列表、引用、代码块后，预览区显示与预期一致。
8. 杀进程后重启，最近文档恢复正常。

设备侧检查：

- 是否有首屏白屏或卡顿
- 是否出现输入后未保存
- 是否有异常日志持续刷屏
- 深浅主题切换后文字可读性是否下降
